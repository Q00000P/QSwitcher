# QSNet — контекстный детектор раскладки

Маленькая сеть, которая отвечает на один вопрос: **какой язык имел в виду человек,
нажав эти клавиши в этом контексте**. Одни веса на мак и винду и на оба направления
(RU→EN и EN→RU). Обучается локально, без API и без torch — только `numpy`.

Слово подаётся не буквами, а **клавишами** в EN-обозначениях: «привет» и «ghbdtn» —
одна и та же последовательность `ghbdtn`. Поэтому сеть одинаково видит слово,
набранное в любой раскладке; направление свапа решается сравнением её ответа
с текущей раскладкой.

## Файлы

| файл | что |
|---|---|
| `qsnet.py` | общий модуль: нормализация в клавиши, признаки, формат QSN1, эталонный инференс на numpy, CLI-проверка |
| `prepare_data.py` | сбор корпуса в `nn/data/` (Tatoeba, частотные списки, синтетика терминала/конфигов, скан кода, личное, `learned.json`) |
| `train.py` | обучение и экспорт `qsnet.bin` |
| `data/personal.txt` | (необязательно) свои примеры: `ru<TAB>днс в конфиге прописал`, `en<TAB>dns<TAB>terminal` |
| `qsnet.bin` | веса — кладутся в ресурсы обеих платформ |

## Запуск (мак)

```bash
cd ~/dev/QSwitcher
python3 -c "import numpy" || python3 -m pip install --user numpy
python3 nn/prepare_data.py
python3 nn/train.py
python3 nn/qsnet.py nn/qsnet.bin ghbdtn
python3 nn/qsnet.py nn/qsnet.bin dns --ctx "cat /etc/resolv.conf" --app terminal
python3 nn/qsnet.py nn/qsnet.bin днс --ctx "прописал в конфиге" --app chat
```

`prepare_data.py` качает Tatoeba (≈110 МБ) один раз, дальше берёт из `nn/data/`.
Если качалка не пробилась — положить `tatoeba-ru.tsv.bz2` / `tatoeba-en.tsv.bz2`
в `nn/data/` руками (ссылки в скрипте). Свои тексты: `--extra-ru file.txt`,
`--extra-en file.txt` (по предложению на строку).

`train.py` по умолчанию: 6 эпох по 2 млн примеров, `buckets=65536, dim=32, hidden=64`
→ `qsnet.bin` 8.4 МБ, минут 10–15 на M5. `--limit-lines 20000 --epochs 1` — быстрая проба.

## Как это устроено

### Нормализация слова → клавиши
- буквы `a–z` — как есть (в нижнем регистре); `[ ] ; ' , . \`` — как есть;
- кириллица — через стандартную ПК-раскладку в EN-символ той же клавиши (`RU_TO_KEY`);
- `\` и `|` → `` ` `` (ё на ПК на `` ` ``, на маке на `\` — одна клавиша-токен);
- всё остальное (цифры, дефис, пробел) в слово не входит → слово не кодируется (`None`).
  Максимум 24 клавиши.

В приложении нормализация идёт через **свою** карту раскладки (LayoutResolver /
LayoutPair): символ → физическая клавиша → её EN-символ. Итог должен совпадать с
`qsnet.to_keys` на стандартной раскладке.

### Признаки слова
Для строки `<` + клавиши + `>`: все подстроки длиной 1..4 плюс признак `=` + клавиши
(слово целиком). Каждая строка → `FNV-1a 32 bit` по ASCII-байтам → `% buckets` →
строка таблицы эмбеддингов. Вектор слова = **среднее** строк. Маркеры `<`, `>`, `=`
в клавиши не входят, коллизий с n-граммами нет.

```
FNV-1a: h = 0x811C9DC5; для каждого байта: h ^= b; h = (h * 0x01000193) & 0xFFFFFFFF
```

### Вход сети (порядок строго такой, `input_dim = dim + 3·(dim+3) + 5 + 2 = 144` при dim=32)
```
[ вектор слова (dim)
| ctx1 вектор (dim) | ctx1 флаг one-hot [ru, en, none]
| ctx2 вектор       | ctx2 флаг
| ctx3 вектор       | ctx3 флаг
| app one-hot [other, terminal, code, browser, chat]
| текущая раскладка one-hot [ru, en] ]
```
- `ctx1` — ближайшее предыдущее слово, `ctx3` — самое дальнее. Нет слова — нули + флаг `none`.
- флаг контекстного слова — его язык **как он на экране** (после наших свапов); для слова, которое в клавиши не кодируется (путь, число), вектор — нули, флаг — по алфавиту.
- `app` — класс переднего приложения (карту bundle id / имя процесса → класс задаём в конфиге; неизвестное — `other`).
- раскладка — та, в которой слово было набрано.

### Сеть
```
h = relu(x · w1 + b1)        w1: [input_dim × hidden], b1: [hidden]
z = h · w2 + b2              w2: [hidden], b2: [1]
P(ru) = sigmoid(z)
```

### Формат файла `qsnet.bin` (QSN1)
```
"QSN1"                          4 байта
u32 LE                          длина заголовка
JSON UTF-8                      заголовок
float32 LE, row-major           тензоры подряд в порядке header.tensors
```
Заголовок: `buckets, dim, hidden, input_dim, keys, apps, langs, ctx_flags, ngram_min,
ngram_max, ctx_words, max_word_len, hash, tensors: [[имя, форма], …], trained, val_acc…`.
Тензоры: `emb [buckets×dim]`, `w1 [input_dim×hidden]`, `b1 [hidden]`, `w2 [hidden]`, `b2 [1]`.
Читать по заголовку, не по зашитым размерам — тогда можно менять `buckets/dim/hidden`
без правки клиентов.

Эталон для портов — `qsnet.QSNet` (`word_vec`, `build_input`, `forward`). Порт на
Swift/C# — это ~100 строк: FNV-1a, сбор n-грамм, среднее строк, один матричный слой.
Тест паритета: выход порта на наборе из `train.SANITY` должен совпасть с
`python3 nn/qsnet.py` до 1e-5.

## Обучение

Данные — `data/corpus.tsv` (`app<TAB>вес<TAB>текст`) и `data/words.tsv`
(`lang<TAB>вес<TAB>слово`). Метка каждого слова — его алфавит в корпусе; так
русское предложение с латинским словом внутри даёт честный пример code-switch.

Аугментация каждую эпоху заново: раскладка правильная в 80% / чужая в 20%;
флаги контекста портятся в 5% (наш прошлый свап мог быть неверным); в 10%
контекст подменяется чужеязычным, в 15% убирается совсем; класс приложения в
10% случайный. Классы уравновешиваются по суммарному весу. Сглаживание меток 0.02,
чтобы вероятности не липли к 0/1 и пороги уверенности что-то значили.

Личные данные: `learned.json` (force → имелся в виду другой язык, stop → этот) с весом 50,
`data/personal.txt` с весом 20.

## Как сеть стоит в Detector (обе платформы)

Порядок: **force/stop из конфига → выученные правила → одиночные буквы (предлоги)
→ щит коротких слов (≤3 буквы, набранные в языке контекста) → сеть → словари.**
Щит выше сети намеренно: `he` в корпусах частое, «ру» — нет, и сеть уверенно
ошибётся ровно там, где мы уже обжигались.

- `p = P(ru)`, `intended = p ≥ 0.5 ? ru : en`, `conf = max(p, 1−p)`;
- `conf ≥ nnThreshold` → решение сети: SWAP, если `intended ≠ набранная`, иначе keep;
- `conf < nnThreshold` → сеть молчит, словарные правила как раньше;
- слова короче `nnMinLen` (умолчание 3) сети не показываем;
- лог: `[det] сеть P(ru)=0.973 (ctx='прописал в конфиге', chat) → SWAP к 'днс'`.

Порт: `Sources/QSwitcher/LayoutNet.swift`, `windows/src/QSwitcher.Core/LayoutNet.cs`.
При старте оба прогоняют `qsnet-selftest.json` (делает `selftest.py`); расхождение
с эталоном > 1e-3 — сеть выключается с записью в лог.

### config.json (обе платформы, на лету)
| ключ | умолчание | что |
|---|---|---|
| `nnEnabled` / `NnEnabled` | true | выключатель |
| `nnThreshold` / `NnThreshold` | 0.85 | порог уверенности |
| `nnMode` / `NnMode` | `primary` | `primary` — сеть до словарей; `arbiter` — только когда словари промолчали |
| `nnMinLen` / `NnMinLen` | 3 | минимальная длина слова для сети |
| `appClasses` / `AppClasses` | {} | `{"terminal": ["qterm"], "chat": ["max"]}` — подстроки bundle id / имени процесса, дополняют встроенную таблицу |

Веса: мак — `make-app.sh` копирует `nn/qsnet.bin` в ресурсы бандла; винда —
csproj встраивает его прямо из `nn/`. Пользовательский файл важнее встроенного:
`~/Library/Application Support/QSwitcher/qsnet.bin`, на винде — рядом с exe или
в папке данных (задел под синк и своё дообучение).

Дообучение — руками из SecureLog/`learned.json`/`personal.txt` через `train.py`,
файл версионируется (`trained` в заголовке).
